# Production Pass 11 — 카메라·환경·성능 품질 보증

Pass 11은 새 보스나 지역을 늘리는 차수가 아니다. 플레이어가 이미 완성된 전 지역을 이동할 때 가장 먼저 체감하는 카메라, 방향 전환, 화면 전환, 명암, 날씨, 지형 연결감과 프레임 안정성을 출시 기준으로 다시 점검한다.

## 1. 화면 전환

- 새 게임, 이어하기, 마지막 서약석 재시작, 시작 화면 복귀에 검은 화면 전환 계층을 사용한다.
- 화면이 완전히 가려진 뒤 위치와 진행 상태를 교체하고, 교체가 끝난 후 천천히 복귀한다.
- 전환 중 전투 입력, 카메라 입력과 물리를 막아 한 프레임 동안 이전 위치가 노출되거나 캐릭터가 움직이는 현상을 방지한다.
- 움직임 감소 설정에서는 전환 노이즈를 제거한다.

## 2. 3인칭 카메라

- 카메라 충돌을 중앙 광선 하나가 아니라 중앙·좌우·상하 다섯 지점에서 검사한다.
- 기둥과 벽 모서리에서는 어깨 오프셋을 줄이고 카메라를 몸 쪽으로 당긴다.
- 장애물에서 벗어날 때는 즉시 튀어나오지 않고 별도의 복귀 감쇠를 사용한다.
- 질주 중 오랫동안 시점 입력이 없을 때만 이동 방향 뒤로 천천히 정렬한다.
- 록온 중에는 어깨 치우침을 줄이고, 수직 보스는 바닥 전조와 보스가 동시에 보이도록 거리와 세로 목표를 제한한다.
- 부활과 이어하기 때 카메라를 캐릭터 뒤에 즉시 재배치한 뒤 화면을 연다.

## 3. 방향 전환과 이동 감각

- X축과 Z축 속도를 따로 잘라 맞추지 않고 평면 속도 벡터 전체의 변화량을 제한한다.
- 대각선 입력과 반대 방향 전환에서도 가속량이 축마다 중복되지 않는다.
- 180도 반전 가속도를 낮추되 입력 반응 자체는 지연되지 않게 한다.
- 공격·회피·방어의 기존 이동 규칙은 유지하고 일반 이동에서만 조향을 완화한다.

## 4. 프레임 안정성

기존 FPS 평균만 보던 자동 해상도 조절을 다음 지표 기반으로 교체한다.

- 평균 프레임 시간
- 95백분위 프레임 시간
- 프레임 간 흔들림
- 지속적인 저하 시간

심한 저하가 이어질 때는 내부 해상도뿐 아니라 블룸, 안개 시트, 재 입자, 활성 횃불 광원과 그림자 갱신 빈도도 단계적으로 줄인다. 순간적인 한 프레임 저하에는 품질이 변하지 않는다. 회복도 장시간 안정 상태가 유지될 때만 단계적으로 이루어진다.

## 5. 환경·날씨·명암

전 지역이 같은 회색 안개를 공유하지 않도록 진행 위치에 따라 다섯 환경 프로필을 부드럽게 혼합한다.

- 하늘 천정색과 지평선색
- 안개 색과 밀도
- 달빛 색과 세기
- 노출값
- 바람 방향과 세기

절차적 하늘 돔에는 이동하는 구름층을 사용하며, 재와 안개는 플레이어 주변을 따라 이동한다. 따라서 맵 후반에서도 날씨가 사라지지 않는다. 바람은 재·안개·깃발에 함께 적용한다.

## 6. 조명과 그림자

- 달빛 그림자 범위를 첫 지역에 고정하지 않고 플레이어 위치를 따라 이동시킨다.
- 그림자 중심을 그림자 맵 텍셀 단위로 맞춰 이동 중 그림자 떨림을 줄인다.
- 품질 저하 단계에서는 그림자 갱신 빈도를 낮춘다.
- 플레이어 얼굴과 상체가 완전히 검게 뭉개지지 않도록 카메라 방향의 약한 보조광을 사용한다.
- 횃불은 가까운 순서대로 제한된 수만 실제 광원으로 계산하고, 먼 횃불은 불꽃 메시만 유지한다.
- 지역별 달빛과 대기 노출값을 톤 매핑에 천천히 반영한다.

## 7. 지형 연결감

기존 주요 길과 보스 경기장의 충돌 지형은 변경하지 않는다. 대신 낮은 비용의 시각 계층을 추가해 평평한 바닥과 절벽·건축물이 따로 놓인 느낌을 줄인다.

- 인스턴싱된 암석 둔덕과 무너진 경계
- 바닥에 쌓인 재 흐름
- 벽과 지면을 연결하는 뿌리·잔해
- 지역별 안개와 바람으로 통일된 깊이 표현

장식은 이동 가능 공간을 좁히거나 보이지 않는 충돌을 추가하지 않는다.

## 8. 개발 진단

`?debug` 주소의 F3 패널에 다음 값을 추가한다.

- 평균·95백분위 프레임 시간
- 현재 내부 해상도 배율
- 효과 절감 단계
- 카메라 확보 거리
- 드로우콜과 삼각형 수

이 값은 성능 문제가 CPU 프레임, GPU 부하, 카메라 충돌 또는 장면 복잡도 중 어디서 생기는지 수동 플레이 테스트 때 구분하기 위한 것이다.

## 알려진 범위

이 차수의 정적 검사는 카메라·성능·환경 코드가 연결됐는지 확인한다. 실제로 카메라가 편안한지, 빛이 충분한지, 특정 GPU에서 프레임이 안정적인지는 배포 빌드에서 사람이 완주하며 확인해야 한다. Pass 12는 Q·E·R 기술, 쿨타임, 보스 카운터·다운과 소환 패턴을 구현하고, Pass 13은 벽 관통·진행 차단·브라우저별 완주 회귀를 담당한다.
