# Ashen Oath 1.0 출시 검증표

`1.0.0-rc.1`은 기능 구현 완료를 뜻하지만, 실제 공개판으로 표기하기 전에 아래 수동 검증을 모두 통과해야 한다. 코드 검사 통과를 플레이 감각 검증으로 대체하지 않는다.

## 완주 검증

- 새 서약으로 시작해 세 보스를 순서대로 처치한다.
- 두 결말을 각각 선택하고 크레디트 이후 시작 화면으로 복귀한다.
- 각 서약석에서 종료한 뒤 이어하기 위치를 확인한다.
- 지름길 개방, 보스 처치, 재 회수와 결말 기록이 새로고침 후 유지되는지 확인한다.
- 보스전 중 사망, 낙사, 탭 전환과 브라우저 종료를 각각 시험한다.

## 조작과 전투

- 키보드·마우스 완주 1회
- 게임패드 완주 1회
- 록온 전환, 벽 근처 카메라, 계단·경사·좁은 통로 충돌 확인
- 세 보스의 모든 기믹에서 전조와 실제 판정이 일치하는지 확인
- 움직임 감소와 공격 전조 강조를 각각 켠 상태에서 보스전 확인
- 회복, 패링, 처형, 회피 무적과 피격 경직이 프레임 저하 중에도 일관적인지 확인

## 브라우저와 성능

- 최신 Chrome 또는 Edge에서 전체 완주
- Firefox에서 시작·저장·보스전·엔딩 확인
- 1920×1080과 1366×768에서 UI 잘림 확인
- 그래픽 프리셋 세 종류와 자동 해상도 조절 확인
- 30분 이상 연속 플레이 후 메모리 증가와 프레임 저하 확인
- WebGL 문맥 손실 또는 그래픽 장치 재설정 시 저장·복구 안내 확인

## 배포 검증

- GitHub Actions의 타입 검사, 프로덕션 빌드와 Pass 10 검증 성공
- 배포 주소에서 새로고침과 직접 경로 접속 확인
- 개발 주소 매개변수 없이 F3·F8이 비활성화되는지 확인
- 콘솔 오류와 처리되지 않은 Promise 거부가 없는지 확인
- npm 잠금 파일을 생성한 뒤 재현 가능한 설치로 전환

## 공개 판정

위 항목 중 완주, 저장 복구, 보스 판정, 브라우저 빌드 가운데 하나라도 실패하면 정식 `1.0.0`으로 표기하지 않는다. 수정 후 다시 `rc` 빌드를 만들고 같은 검증을 반복한다.
