# Release Candidate Pass 10 — 출시 후보 검증과 차단 오류 수정

이번 차수는 새 보스나 지역을 추가하지 않는다. 처음부터 두 결말까지 이미 연결된 게임을 실제 공개 가능한 상태로 묶기 위해 저장, 브라우저 수명주기, 접근성, 성능과 출시 화면의 차단 오류를 우선 수정한다.

## 차단 오류 수정

### 엔딩 기록 누락

기존 저장 함수는 결말 연출이 시작되면 저장을 거부했다. 따라서 `endingsSeen`에 선택이 추가돼도 브라우저 저장소에는 남지 않을 수 있었다. 결말 선택 직후 즉시 저장 요청을 만들고, 결말 잠금 중에도 명시적인 저장은 허용한다.

### 크레디트 이후 탈출 불가

크레디트가 끝난 뒤 조작이 잠긴 채 남는 구조를 수정했다. 크레디트 후반에 다음 선택이 나타난다.

- 현재 결말과 진행을 저장하고 시작 화면으로 복귀
- 기존 저장을 지우고 새 서약 시작

### 개발 입력 노출

`F3`, `F8` 개발 입력은 일반 배포 주소에서 작동하지 않는다. 주소에 `?debug`가 있을 때만 활성화한다.

## 브라우저 안정성

- 탭이 숨겨지면 즉시 저장한 뒤 전투를 일시정지한다.
- `pagehide`와 `beforeunload` 모두에서 안전 저장을 시도한다.
- WebGL 문맥 손실 시 입력과 카메라를 중단하고 저장한다.
- 그래픽 문맥이 복구되면 저장된 상태를 이용하도록 페이지를 다시 불러온다.
- 포인터 잠금 API가 없는 환경에서는 기존 드래그 카메라가 계속 동작한다.
- 게임패드만 사용해도 메뉴 항목 이동, 선택, 뒤로가기와 설정값 조절이 가능하다.

## 기록 보호

기존 저장이 있을 때 `새 서약`을 한 번 누르는 것만으로 기록이 삭제되지 않는다. 4.2초 안에 `기존 기록을 지우고 시작`을 다시 선택해야 새 게임이 시작된다.

## 접근성

### 움직임 감소

- 카메라 타격 충격을 설정값의 18%로 제한
- 색수차와 필름 입자 움직임 감소
- HUD·메뉴·엔딩 전환 애니메이션을 거의 즉시 완료
- 핵심 공격 동작과 판정 시간은 변경하지 않음

### 공격 전조 강조

- 레이드 기믹 경고의 배경과 글자 대비 증가
- 위험 진행 막대 두께 증가
- 록온 표식과 3페이즈 보스 UI 대비 증가
- 후처리의 위험 구간 명암 분리 강화
- 세 보스의 실제 바닥 원·직선·도넛 전조 재질을 더 밝고 불투명하게 표시
- 최종 보스의 안전 구역은 청색 계열로 분리해 위험 전조와 색·명도 모두 다르게 표시

### UI 크기

90~125% 범위에서 UI 기본 글자 크기를 조절한다. 설정 화면은 낮은 해상도에서도 잘리지 않도록 내부 세로 스크롤을 허용한다.

## 성능 보정

3인칭 카메라가 매 프레임 생성하던 임시 `Vector3` 객체를 재사용 필드로 바꿨다. 록온, 충돌 카메라와 높은 보스 프레이밍에서 발생하던 지속적인 가비지 컬렉션 압력을 줄인다.

## 출시 후보 검증 범위

- HTML ID 중복과 필수 UI 요소
- 엔딩 저장과 크레디트 이후 버튼
- 세 보스의 파일·페이즈·전용 경기장 회귀
- 서약석과 보스 진행 순서
- 저장 손상 정규화 코드 유지
- 접근성 설정의 저장·UI·렌더 파이프라인 연결
- WebGL 문맥 손실과 브라우저 숨김 처리
- 일반 배포에서 개발 키 비활성화
- 증분 번들 선행 커밋과 fast-forward 적용

## 남은 검증 한계

현재 제작 환경에서는 npm 레지스트리 연결이 시간 초과되어 실제 Three.js·Rapier·Vite 의존성을 사용한 브라우저 완주 테스트와 `package-lock.json` 생성을 수행할 수 없었다. 따라서 `1.0.0-rc.1`은 코드와 구조 기준 출시 후보이며, GitHub Actions의 실제 타입 검사·빌드와 배포 URL의 수동 완주 테스트가 최종 공개 전 필수다.


정식 `1.0.0` 공개 전 수동 통과 기준은 `docs/RELEASE_VALIDATION.md`에 고정한다.
